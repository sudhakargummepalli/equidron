# Decisions

One line per decision: date, decision, reason. Newest at the bottom.

- 2026-10-19 · Work in the owner's own repository (sudhakargummepalli/equidron) instead of a fork · the owner is the original author; the PDF's "fork it" step is for students.
- 2026-10-19 · The test count is 59, not the PDF's 51 · commit 8471570 (bank-statement payments) came after the PDF's commit 7639c8c and added 8 tests. "All original tests pass" means all 59.
- 2026-10-19 · Keep the bank-transfer check against a Google Sheet statement (src/statement.js) alongside SimulatedProvider · it postdates the PDF; Phase 8 replaces both with a real gateway in test mode, and the check stays for tests and demos.
- 2026-10-19 · The deploy previews and branch protection in Phase 0 are left to the owner · they change Netlify and GitHub settings, which the working rules reserve for the owner.
- 2026-10-19 · Add `.env` to .gitignore · local secrets must never be committed.
- 2026-10-19 · audit_log ids are GENERATED BY DEFAULT, not ALWAYS as in Appendix A · every other table uses BY DEFAULT, and the test reset and database restores copy rows with their ids, which ALWAYS refuses.
- 2026-10-19 · One Phase 1 migration (20261019000000_accounts_and_audit.sql) adds every Phase 1 table and column, and is safe to run again · existing staff get the admin permission so nobody loses access; existing users count as email-verified.
- 2026-10-19 · Codes for sign-up and password reset wait in an outbox table that only Ops admins can read · no email provider until Phase 10. Risk: an admin can read codes. Acceptable on sample data; Phase 10 replaces it.
- 2026-10-19 · Sample accounts can't sign in at all unless EQUIDRON_SEED_DEMO=1, not only "not seeded" · the live database was seeded earlier with the shared password, so gating the seed alone would leave it working. The demo site must set EQUIDRON_SEED_DEMO=1 in Netlify before this merges, or its sample logins stop.
- 2026-10-19 · Two-step sign-in is opt-in for sellers and staff in Phase 1 · forcing it would lock out the shared sample accounts. Recommend making it required for admin staff before go-live (Phase 15).
- 2026-10-19 · Lockout counts failures per email, not per IP address · the function sees no reliable client IP yet; Phase 15 adds Netlify rate limits on public endpoints.
- 2026-10-19 · Local cookies have no Secure flag · the local server is plain http://localhost; the Netlify function adds Secure.
- 2026-10-19 · TOTP secrets are stored as-is in users.totp_secret · the server must read them to check codes; encrypting them at rest is a Phase 15 hardening item.
- 2026-10-19 · CSP allows images from any https site and inline styles · sellers link product photos until Phase 11, and the pages use style attributes. Scripts stay limited to this site and cdnjs, without eval.
- 2026-10-19 · Phase 2 is split into 2a (concurrency: no global lock, row locks, idempotent checkout, PostgreSQL in CI) and 2b (column types, search, paging) · each is reviewable on its own, and 2a fixes the bigger risk first.
- 2026-10-19 · Stock is reserved with a guarded UPDATE rather than SELECT ... FOR UPDATE · one statement both checks and reserves; rows are taken in (offer_id, warehouse_id) order to avoid deadlocks.
- 2026-10-19 · The idempotency key travels in the request body (idempotency_key), scoped to the signed-in customer · handleApi passes no request headers today; webhooks in Phase 8 will use the provider's event id.
- 2026-10-19 · Row-Level Security (optional in the PDF) is left for later · the area checks in api.js already scope every query, and RLS needs a connection role per request that Netlify Database setup would have to change.
- 2026-10-19 · The CI PostgreSQL service uses trust authentication · it is a throwaway database inside one CI run, and this keeps any password out of the repository.
- 2026-10-20 · Existing text times are read as UTC by the Phase 2b migration · the Netlify functions, which wrote the live data, run in UTC. Local data/pg folders written in IST will look 5½ hours off: use `node app.js --reset`.
- 2026-10-20 · Epoch-number columns (sessions.expires_at, login_attempts.at, auth_codes) stay DOUBLE PRECISION · they were never text, and the code compares them as seconds.
- 2026-10-20 · The search index is an expression index, not a stored tsvector column · the test reset copies whole rows back, which a generated column refuses; catalog.SEARCH_VECTOR repeats the expression so queries use the index.
- 2026-10-20 · Typo matching runs only when fewer than 5 products match exactly, with word_similarity >= 0.35 · it keeps exact results first and avoids noise; it is off where pg_trgm is unavailable.
- 2026-10-20 · The 2026-10-17 laptops data migration is left as it is · applied migrations are never edited. After Phase 2b it is either already applied or a no-op (it runs before the first seed), so its fill test now runs on the old column types.
- 2026-10-20 · Search pages default to 24 results, at most 60 · 60 was the old fixed cap; smaller pages load faster and paging reaches every match.
- 2026-10-21 · The first listener is the order confirmation email (into the outbox) · there are no agents until Phase 4, and it proves the whole path: event, job, handler, outbox.
- 2026-10-21 · Errors go to an error_log table always, and to Sentry only when SENTRY_DSN is set, through its HTTP envelope API · no SDK dependency, and the System page works without any outside account.
- 2026-10-21 · The weekly backup is a JSON export of every table except sessions, kept in Netlify Blobs · the app has no pg_dump on Netlify; a restore test in the test suite proves it can be read back. A full database snapshot from the provider is still the owner's safety net.
- 2026-10-21 · The worker copy limit uses slot rows in settings that expire after 15 minutes · advisory locks are per connection, and a pooled function can't hold one for a whole run.
- 2026-10-21 · @netlify/blobs is pinned to 11.1.2 (30 Sep 2026), not the newest 11.1.4 · newly published versions carry more supply-chain risk; a few weeks old is the house rule.
- 2026-10-21 · The shipment simulator moves every active shipment one stage every five minutes, like the Ops button · it is a demo stand-in until real couriers in Phase 9, and can be switched off.
- 2026-10-22 · Phases 0–3 are already in `main` (pull requests #1–#5), so `phase-4-agent-runtime` is cut from `phase-3-jobs`, whose content equals `main`, and its pull request goes into `main` · the handoff note saying nothing was merged was out of date; `git diff main phase-3-jobs` is empty and GitHub shows all five merged.
- 2026-10-22 · `agents.id` is a text key, so `--reset`, the backup restore and the test reset only call `setval()` when the table has a real id sequence · a text id has none, and asking for one failed with "COALESCE types text and integer cannot be matched".
- 2026-10-22 · An approval runs from its stored payload and closes its run (status `waiting` → `done`); the follow-up turn that tells the customer waits for Phase 5 · finishing a case needs message history the run does not keep yet, and Phase 5 is where real cases begin.
- 2026-10-22 · The store assistant keeps `claude-opus-5-5` after moving onto `runAgent()` · the routing table offers Haiku, Sonnet and Opus, but swapping the live chat changes cost and quality at once; it is one setting on the Agents page once the owner wants to compare.
- 2026-10-22 · A tool call the policy denies is answered with an error result and the run continues; it is not retried · the model can then choose an allowed tool, the deny is a recorded step, and retrying the same call would only spend tokens.
- 2026-10-22 · Cost is a price table in `src/agents/models.js`; an unpriced model costs 0 and logs a warning · inventing a price would make budgets and the Ops spend figures look precise when they are not.
- 2026-10-22 · Two runs can both pass the budget check before either records its cost, so a day can overspend by about one model call · the fix would be a global lock, which Phase 2 removed on purpose; the exposure is cents and each run stops at its next check.
- 2026-10-22 · The policy check lives in `decide()` and the runtime also stops a run when agents are paused or the budget is gone · belt and braces: a future caller of `executeTool()` cannot skip the check, and a run in flight stops even between two tool calls.
- 2026-10-23 · Agent job kinds run outside the job's transaction (`registerHandler(kind, fn, { outsideTransaction })`) · a run waits minutes on a model, and holding a transaction that long would lock rows and lose the trace on a crash; the job is marked done afterwards, and a retried job is stopped by a check for an existing run on the same subject.
- 2026-10-23 · Fulfilment Watch starts at L1 (shadow), although the PDF's agent table says L2 · §4 of the same PDF says every new agent starts at L1; starting in shadow means its messages can be compared with people's before anything reaches a seller or customer.
- 2026-10-23 · The Daily Brief is queued by the minute tick at 08:00 IST rather than a `30 2 * * *` scheduled function · Netlify runs scheduled functions only in production, so a tick-based queue also works locally and catches up after downtime; the dedupe key is the India day, so it still happens once.
- 2026-10-23 · The Ops task for a twice-late shipment is written by SQL in the job, not decided by the model · the rule must hold whether or not the model notices, and opening an internal task needs nobody's approval.
- 2026-10-23 · A seller nudge or customer warning is limited to one per shipment per day, recorded as an event (`shipment.nudged`, `shipment.warned`) · the check lives in the tool, so it holds even when a person approves the same message twice.
- 2026-10-23 · The agent's verdict is stored on the submission (`agent_decision`, `agent_confidence`, `agent_run_id`), and the agreement score counts only cases a person decided · auto-approved submissions have no human decision to agree with, and "escalate" counts as a request for a person, not a match.
- 2026-10-23 · The 30 listing eval cases ship in the repository (`src/agents/evals/listing-review.json`) and are loaded on first use · an eval set belongs to the agent's code, and a fresh database then works without a seeding step.
- 2026-10-24 · Guardrails refuse card numbers, attempts to rewrite an assistant's instructions, and abuse; they only flag contact details and odd listing text · a heuristic must not block a person's real work, and a flagged listing is already held for review, so a flag is enough.
- 2026-10-24 · A guardrail flag on a listing adds a review reason, so that listing can never be approved automatically · the automatic path would otherwise hide exactly the case a person should see.
- 2026-10-24 · Rate guardrails count real rows (a seller's submissions in the last hour), not a separate counter · a counter drifts; the rows are the truth, and the check costs one query.
- 2026-10-24 · Guardrail events keep a masked snippet, never the original text · the same rule as logs: an event is a record of what happened, not a second copy of personal data.
